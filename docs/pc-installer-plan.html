Rough plan · v0.1 · 2026-11-15

PC Installer for Skate 3 AR

One desktop app, Windows and Linux, that puts the Quest app on the headset, shows the three engines (sk8, Skate 3, THUG2), and turns the user's own game copy into a ready bundle on the PC and pushes it over USB. It replaces today's four manual steps (run skate3rust.exe, skate a minute, run MAKE-QUEST-ZIP.bat, copy the zip, import in the headset).

Summary

Build it in Rust with egui/eframe

One native binary per OS, no webview (sidesteps WebKitGTK + NVIDIA problems on Bazzite), and it can link skate-data directly for audio pre-decoding and bundle checks. Tauri is the runner-up if a richer UI matters more.

Convert on the PC, push a finished bundle

The headset never unzips anything. The installer writes the final folder tree straight into the app's files directory with adb, file by file, so it can resume and needs no 2x space on the Quest.

All three engines in one app

One installer, one APK with sk8, Skate 3 and THUG2 compiled in (no Meta store target, so no store-build split). Skate 3 and THUG2 show "Needs your game files" until the user imports their own copy. No game files ever ship.

"Install the base app" is read as sideload the Quest APK over USB (that is what the README tells users to do by hand with adb install -r skate3ar.apk). A desktop build of the game is possible later but is not in v1; see open question 1.

Proposed crate layout (in the fork, not upstream yet): crates/sk8-installer (eframe UI) on top of crates/sk8-installer-core (device, jobs, bundles; no UI, testable, also exposes a CLI: sk8-installer push --engine skate3 ...). The installer has no engine code of its own; the engines live in the APK. It only converts and pushes data.

Talking to the Quest

  • adb. Use an adb server that is already running (SideQuest / Meta Quest Developer Hub start one on port 5037; starting a second one breaks theirs). If none, start our own copy of Google platform-tools, downloaded on first run from Google's URL and hash-pinned, the same way the desktop setup already downloads extract-xiso (tools/setup.py; its docs were removed from the tree, see git history). Alternative to evaluate: the adb_client crate (pure Rust, talks USB directly), which would avoid shipping Google's binary.
  • Headset state machine: not seen → seen but unauthorized (put on headset, tick "Always allow", Allow) → device → app installed? (pm list packages, dumpsys package for versionName) → free space (df /sdcard).
  • Linux USB permission: a udev rule for Meta's vendor ID, e.g. SUBSYSTEM=="usb", ATTR{idVendor}=="2833", MODE="0660", TAG+="uaccess" in /etc/udev/rules.d/51-quest.rules. The installer detects "USB device present but adb can't open it" and offers a one-click pkexec install of the rule (or a copy-paste command). /etc is writable on Bazzite; check first whether Bazzite already ships Android rules.
  • Windows driver: Quest often needs Meta's "Oculus ADB Driver". Detect "Quest seen as MTP only" and link to / run the driver installer.
  • Wireless adb (later): after a first USB connection, adb tcpip 5555 + adb connect <ip>. Handy for re-pushing updates; too slow and flaky for a first 5 GB push, so USB stays the default.
  • Always am force-stop the app before pushing and writing markers.

Which APK, and where data lands

There are two Quest builds: com.andrewnakas.skate3ar (crates/buildar-quest, clean tier + retail) and com.andrewnakas.sk8ar (crates/sk8-quest, store build, no importer). Only skate3ar can run Skate 3 data, so the installer installs that one. If it finds only sk8ar, it explains that sk8 works but Skate 3 needs the other app (both can be installed side by side; different package names).

PhaseLayout under /sdcard/Android/data/com.andrewnakas.skate3ar/files/App change
v1 (Skate 3)assets/ (with private/game.json), Skate3RustEngine/audio-pcm-cache/, use-retail-data, plus a new assets/bundle.jsonNone. This is exactly what push-assets.sh and the in-app importer already produce.
v2 (multi-engine)engines/skate3/…, engines/thug2/Data/…, each with bundle.json; engine text file = sk8|skate3|thug2clean::wanted() generalised to an engine pick; still requires "marker and data present" so a bad marker can't strand the player. Keep reading use-retail-data for old installs.

Note: push-assets.sh has to mkdir every folder from adb shell first because adb push can't create folders inside another app's files dir. The installer does the same (one generated script, as the script does).

  "total_bytes": 4710000000

  • The installer keeps the finished bundle in a PC cache (%LOCALAPPDATA%\SK8Installer\bundles, ~/.local/share/sk8-installer/bundles) so re-pushing after a reinstall or a factory reset takes minutes, not a reconversion. User can delete it from Settings.
  • The APK states which bundle format values it reads (an asset file or the installer's release index maps APK version → format). Mismatch = "Update available" on the engine card.
  • A new converter version (same signal the desktop updater already uses: "changed extractor fingerprints", removed from the tree; see git history) also shows "Update available"; the installer remembers the source path and rebuilds only when the user agrees.
  • "Save bundle as zip" stays as an export for people without adb; the in-app Import (xr/ui/import.rs) still reads it.

How the installer and the app detect engines

  • sk8: always ready once the APK is installed (compiled in; --check-assets just prints SKATE_ASSETS_READY).
  • Skate 3: installer reads files/assets/bundle.json over adb (falls back to "is private/game.json there" for bundles from the old zip path). Same test as Import::installed().
  • THUG2: compiled into the APK; ready when engines/thug2/bundle.json is there and its file list checks out.
  • The in-app "Skate 3 data" menu grows into an "Engine" menu listing what is installed, so switching does not need the PC.

One build with every engine

Scope: the user is not targeting the Meta store, so the THUG2 and Skate 3 engine code ship in the normal installer and APK. The only gate is data: an engine turns on when the user's own game files are imported. Concretely:

  • The APK the installer pushes is buildar-quest built with retail plus a new thug2 feature (the THUG2 core from the decomp, cross-compiled for aarch64-linux-android and linked in). Keeping thug2 a cargo feature costs nothing and keeps the build tidy, but releases always turn it on.
  • No engine downloads, no feeds, no plugin ABI. The engine code is small next to the data (a few to a few tens of MB vs 1.4–5 GB of imported data), so splitting it out for size doesn't pay off. The only case for it would be a store build again, which is out of scope.
  • The store build (crates/sk8-quest, com.andrewnakas.sk8ar) stays as it is in the repo but the installer doesn't use it.

Updates

  • Installer: checks a JSON release index (GitHub Releases), sha256 + minisign signature, Stable/Latest channels like the old desktop updater (removed; see git history). On Linux AppImage, replace the file in place; on Windows, run the new NSIS installer.
  • APK: compare headset versionName with the index; adb install -r. Handle INSTALL_FAILED_UPDATE_INCOMPATIBLE (different signing key): uninstalling deletes the files dir, so warn and offer to re-push the cached bundle afterwards.
  • Bundles: per-file diff via bundle.json; only changed files are pushed.

2. Engine import pipelines

Skate 3 (Xbox 360)

What exists: the desktop setup (tools/setup.py → tools/prepare_assets.py + tools/asset_pipeline/*, shipped frozen with Python/NumPy/Pillow as the setup helper) extracts the ISO with a hash-pinned extract-xiso, reads miscload.big, miscboot.big, db.big, the CAC archive and each worldDIST_*.big, and writes assets/ with private/game.json. Sound banks are XMA2 and decoded by the ffmpeg binary (skate-data/src/audio/ffmpeg.rs) into %LOCALAPPDATA%\Skate3RustEngine\audio-pcm-cache\*.v3.pcm, but only lazily while playing (audio/catalog.rs) — that is why users are told to "skate for a minute". make-bundle.ps1 then copies both into quest-data/ and zips it.

Space (estimates to measure): PC ~7–8 GB ISO + ~8 GB extracted workspace (deleted after) + ~5 GB bundle cache; Quest ~5 GB (the doc's number). Pushing the folder directly avoids today's zip-plus-unzip, which needs ~2x on the headset.

Resume: each step writes into a temp dir and renames on success, with a job.json checkpoint; the setup pipeline already keeps failed workspaces and logs. Push compares remote size (and sha256 for small files) per file, so a pulled cable resumes where it stopped.

Fast path for v1: users who already ran skate3rust on Windows skip steps 1–3; the installer finds their data, pre-decodes audio, and pushes. That alone removes MAKE-QUEST-ZIP and the manual copy, and works on Linux if they copy the converted folder over.

THUG2 (PC)

What we need: the PC game's Game/Data tree (~1.4 GB: pre/*.prx incl. qb_scripts.prx and per-level *_scripts.prx/col/scn, anims, skeletons, models, levels, sounds, streams, textures…), as found in ~/Games/THUG2-extract/Game/Data. The headless core runs from that folder (thug2-headless/app/headless_main.cpp).

  • The data importer can be built and tested before the engine runs on the Quest; until then the card says "Data ready · engine coming in a later app version".

4. Phased plan

One developer, rough. All of it lives in the fork, which will publish its own GitHub releases; no upstream PRs.

  • eframe shell with the app palette and fonts; adb detection and the headset state machine; udev rule flow on Bazzite; Oculus driver check on Windows.
  • Answer open questions 1–3.

Base app install
  • Download APK from the release index, verify sha256, adb install -r, version check, key-mismatch handling.

  • Find skate3rust installs / accept a folder or Skate3-Quest.zip; audio pre-decode step in Rust; bundle.json; resumable push; marker. Retires MAKE-QUEST-ZIP.bat for most users.

  • Self-update, wireless adb, code signing, Flatpak (maybe), translations of error text, telemetry-free crash log export.

Open questions

What does "install the base app" mean?Plan assumes: sideload the Quest APK over USB. Should it also install the desktop game (skate3rust-style Windows build; there is no Linux desktop build today)?
Which package name?Assumed the all-engines APK keeps com.andrewnakas.skate3ar so existing installs and imported Skate 3 data carry over. Should the old store-style sk8ar build be retired?
Build the THUG2 core for Android: in the main workspace or prebuilt?It's C++ with a CMake build (thug2-headless). Linking it via a build script in a new crate is simplest for CI; a prebuilt .a per release is the alternative.
Is Linux Skate 3 ISO conversion needed in v1?Or is "Linux can push an already-converted folder; ISO conversion on Windows" OK until M3?
Which THUG2 files does the Quest engine really need?Whole Data (1.4 GB) or a traced subset; which THUG2 PC versions must be supported (1.0, 1.01, others)?
Keep bundles on the PC?~5–7 GB cache for fast re-installs vs. disk use. Default on, with a Delete button?
Distribution and signingThe fork is moving to its own GitHub releases. Should installer builds go there too, and is a Windows code-signing cert in budget? AppImage-only on Linux OK, or Flatpak wanted?
Wireless adb in v1?Plan puts it in M6.
